Point your agent at this page and it can install and run OpenWork for you.

<Warning>
Don't use `npx openwork` or `npm install openwork`. The npm package named `openwork` is a different project. The server package is **`openwork-server`**.
</Warning>

<Note>
This is a self-hosted-only fork. The hosted OpenWork Cloud, its web app, its
team/organization setup, and the `api.openworklabs.com/mcp/agent` MCP Gateway
were removed from the project. There is no hosted MCP endpoint to connect an
agent to, and no hosted download page. What follows is entirely self-hosted.
</Note>

## Run the server

```sh
npm install -g openwork-server
openwork-server
```

It writes configuration to `~/.config/openwork`, listens on `127.0.0.1:8787`,
and prints a URL. Open it and you are signed in — there is no account to
create.

Then give the agent an authorized workspace root and a task. A good first one:

```text
Use OpenWork to summarize the folder /home/me/projects/thing.
```

See [Self-host](/start-here/self-host) for the full picture, including how to
run the browser UI instead of the desktop app.

## Configure a model

The server ships no model catalog and no default provider. Have the agent set
one up:

| Goal | Ask for |
|---|---|
| Local models | "Set up Ollama as the model provider." |
| Your own gateway | "Configure the provider base URL to point at my LiteLLM instance." |
| An API key | "Add my Anthropic API key as a provider." |

The pages are [Use local models](/start-here/connect-your-stack/use-local-models),
[Add a custom LLM](/start-here/connect-your-stack/add-a-custom-llm), and
[Add an Anthropic API key](/start-here/connect-your-stack/add-anthropic-api-key).

## Install the desktop app

The desktop app is a separate download. It connects to a running server, so
start the server first.

| OS | Install |
|---|---|
| macOS (Homebrew) | `brew install --cask openwork` |
| macOS, Windows, Linux | Download the build for your platform from [GitHub releases](https://github.com/different-ai/openwork/releases) |

Then [run your first task](/desktop-app/first-task).

## Skills

Skills are directories on disk. An agent can write them for you — see
[Create a skill from chat](/start-here/do-work-with-it/create-a-skill-from-chat)
— and copy them between machines with
[Share your setup](/start-here/do-work-with-it/share-your-setup). Skills follow
the [Agent Skills](https://schemas.agentskills.io) `SKILL.md` convention, so an
agent that already understands that format can write one without further
instruction.

## Connect an MCP server

MCP servers are configuration, not an account. Have the agent add one:

```text
Add the Context7 MCP server (https://mcp.context7.com) to OpenWork.
```

See [Add an MCP server](/start-here/connect-your-stack/add-an-mcp-server) and
[Connect services](/start-here/connect-your-stack/connect-services).

## What an agent should not do

- **Do not point OpenWork at a hosted OpenWork endpoint.** There isn't one.
- **Do not bind the server to `0.0.0.0`.** It authorizes anything that reaches
  the port. Loopback, or your own authenticating proxy.
- **Do not set `OPENWORK_ENABLE_FREE_INFERENCE=1` without
  `OPENWORK_FREE_INFERENCE_ORIGIN`.** The free route has no default origin and
  makes no request unless you name one.
