## There are no plans

This is a self-hosted-only fork. OpenWork's hosted control plane has been
removed from the repository, and with it every commercial tier: no Free/Team/
Enterprise split, no per-seat billing, no managed inference add-on, no hosted
computers, no sales process, and no subscription to talk to anyone about.

You run the software. There is nothing to purchase and no account to create.

## How licensing works

**Everything in this repository is MIT licensed.** See [`LICENSE`](https://github.com/different-ai/openwork/blob/dev/LICENSE).

Upstream OpenWork used a directory-split license similar to GitLab's: MIT
outside `ee/`, and a source-available "OpenWork EE License" inside `ee/` for the
organization control plane. This fork **deleted `ee/`**, so the split no longer
applies and the EE license text is gone from the repository.

That means:

- Use it commercially or not, for any number of users.
- No seat limits, no user-count thresholds, no evaluation clock.
- Audit it: the whole thing is public and MIT, with no subscription tier to
  unlock the rest of it.

Versions of OpenWork released upstream *before* this fork point were governed by
the license text they shipped with — including the FSL-1.1-MIT releases that
preceded the EE license split. If you are vendoring a specific published version,
read the `LICENSE` file at that tag.

## Third-party components

Third-party dependencies remain under their own upstream licenses. See
`LICENSES/` and the per-file notices vendored alongside vendored code.

## What replaced the paid features

Most of what the paid tiers sold was *control-plane* functionality — the things
a hosted service provides on your behalf. Running the server yourself means you
get the equivalent directly:

| Was a paid feature | Now |
| --- | --- |
| Managed inference ("OpenWork models") | Point a provider `baseURL` at your own gateway, or run local models. See [Add a custom LLM](/start-here/connect-your-stack/add-a-custom-llm). |
| Cloud computers / hosted workspaces | Run `openwork-server` on your own host. See [Self-host](/start-here/self-host). |
| Shared LLM providers and team collections | Configure providers and skills per deployment. See [Share your setup](/start-here/do-work-with-it/share-your-setup). |
| SSO / SCIM / RBAC | Your authenticating reverse proxy, in front of a server that should never be exposed directly. |
| Desktop policies and white-labeling | [On-prem branding](/start-here/on-prem-branding) and your own configuration. |
| Audit logs | The server's own logs and data path. |

<Warning>
  Some of those rows are real gaps rather than equivalents — there is no
  built-in SSO, SCIM, or audit log in this fork. Put your own infrastructure in
  front of it. In particular, never expose the server directly: it authorizes
  whatever can reach the port.
</Warning>
