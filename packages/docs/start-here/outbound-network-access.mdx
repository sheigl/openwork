<Note>
This is a **self-hosted-only fork**. OpenWork's hosted control plane has been
removed, so most of what this page used to list is gone. The table below is
generated from the canonical manifest,
[`docs/enterprise/outbound-access.json`](https://github.com/different-ai/openwork/blob/dev/docs/enterprise/outbound-access.json),
which CI guards with `node scripts/check-outbound-access.mjs`.
</Note>

## What this fork reaches out of the box

Very little. A default build makes **no** request to OpenWork:

- No model catalog. `OPENCODE_MODELS_URL` is unset, so the key is omitted entirely.
- No control plane. There is no default Den base URL in either the app or the
  desktop shell.
- No analytics. The PostHog project key is not baked in; every send path in
  `analytics.ts` returns early on an empty key.
- No feedback or documentation link. `buildFeedbackUrl` returns `null` and the
  Docs menu item hides itself.

What remains is: GitHub (installer/updater), npm (the `npx` UI-control MCP), and
whatever providers and MCP servers **you** configure.

## Blocked if you would rather not

| Host | Requirement | Why it is reached | What breaks when blocked |
| --- | --- | --- | --- |
| `github.com` | Required in practice unless mirrored | Desktop installer and updater release URLs, GitHub issue links, and GitHub plugin source URLs. | Desktop install/update downloads cannot start; GitHub issue and plugin-source links may not open. |
| `release-assets.githubusercontent.com` | Required in practice unless mirrored | Current GitHub release-asset redirect target, reached after `github.com` redirects installer and updater downloads. | Downloads start from `github.com` and fail partway through. |
| `objects.githubusercontent.com` | Required in practice for legacy/rollback | Legacy GitHub release-asset redirect target, kept so older clients and staged rollbacks keep working. | Downloads can fail partway through on those paths. |
| `registry.npmjs.org` | Required in practice unless npm is mirrored | `npx` package resolution for `openwork-ui-mcp` and development-only MCP helper commands. | The OpenWork UI-control MCP is unavailable. |
| `opencode.ai` | Optional | Fallback OpenCode installer command plus OpenCode auth/docs links and config schema identifiers. | Guided fallback installation and OpenCode web links fail; packaged builds still use bundled OpenCode. |

For a fully isolated deployment, mirror the installer artifacts, the npm
packages `npx` fetches, and any model catalog you use. See
[Air-gapped deployment](/start-here/air-gapped-deployment) and
[Installer delivery](/start-here/installer-delivery).

## Everything the source contains

This is the full manifest, by connection kind. Hosts listed as `fetched` or
`subprocess` are contacted at runtime; `link-only` entries are user-facing links;
`redirect-target` and `schema-string` entries are not fetched directly.

### Reached by a subprocess

| Host | Requirement | Why it is reached | What breaks when blocked |
| --- | --- | --- | --- |
| `ghcr.io` | optional | Container registry for self-hosted deployments pulling their own images. | A containerised self-hosted deployment cannot pull images from GitHub Container Registry. |

### Redirect targets

| Host | Requirement | Why it is reached | What breaks when blocked |
| --- | --- | --- | --- |
| `objects.githubusercontent.com` | required-in-practice | Legacy GitHub release-asset download target. GitHub has migrated to release-assets.githubusercontent.com, but allow both so older clients and any staged rollback keep working. | OpenWork downloads start from github.com and then fail partway through if GitHub serves this legacy redirect target and it is blocked. |
| `release-assets.githubusercontent.com` | required-in-practice | Current GitHub release-asset download target reached after github.com redirects installer and updater downloads. Verified live against a real OpenWork release asset. | OpenWork downloads start from github.com and then fail partway through when the redirect target is blocked. |

## Opt-in providers and MCP hosts

These are only needed when you enable the corresponding provider or MCP server:

| Host | Requirement | Why it is reached | What breaks when blocked |
| --- | --- | --- | --- |
| `api.anthropic.com` | Opt-in | Direct native Anthropic requests when an Anthropic provider is configured. | Configured native Anthropic models cannot generate responses. |
| `api.openai.com` | Opt-in | Direct OpenAI Realtime voice, image generation, and native model requests when an OpenAI provider is configured. | Direct OpenAI voice, image, or native model requests fail. |
| `openrouter.ai` | Opt-in | Direct native OpenRouter model requests when configured. | Configured native OpenRouter models cannot generate responses. |
| `mcp.notion.com`, `mcp.linear.app`, `mcp.sentry.dev`, `mcp.stripe.com`, `mcp.context7.com`, `mcp.slack.com` | Opt-in | Built-in MCP Quick Connect presets. | That specific MCP preset cannot connect. |
| `api.githubcopilot.com` | Opt-in | Example remote MCP server URL; only reached if you configure that URL. | Only that MCP connection fails. |

Override any provider or MCP destination with the provider's `baseURL` or the MCP
server URL setting.

## Verifying it yourself

The auditor compares the manifest against the actual source, so if you add an
outbound request without recording it, CI fails:

```bash
node scripts/check-outbound-access.mjs
```

The JSON manifest remains the ownership point for exact host metadata,
requirement level, override name, and blocked effect. Use this page for review
conversations and the JSON file for automation.
