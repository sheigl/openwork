title: "OpenWork vs OpenCode models"
description: "OpenWork does not ship a model catalog in this fork — where models actually come from"
---

<Note>
This fork has **no OpenWork inference service**. The hosted model catalog and
usage-bucket system went away with the control plane. There is nothing to
subscribe to and no dashboard to check.
</Note>

OpenWork is a client. The models come from whatever provider you configure:

| Source | Where you manage it | What it controls |
| --- | --- | --- |
| Your own API key (Anthropic, OpenAI, OpenRouter) | The provider's own console | Billed directly to you; OpenWork just sends requests |
| A local model server (Ollama, or any OpenAI-compatible server) | The local server | Runs on your hardware; nothing leaves the machine |
| Your own gateway (LiteLLM, Bifrost, or your own) | The gateway's console | Routing, quotas, and per-person keys — you own all of it |
| OpenCode Zen / Go | [OpenCode Go](https://opencode.ai/go) and [OpenCode auth](https://opencode.ai/auth) | OpenCode-managed models, subscription, and API access |
| ChatGPT sign-in | Your ChatGPT account | Uses your ChatGPT access directly |

## There is no model catalog default

In this fork, `OPENCODE_MODELS_URL` is unset by default, and the server omits
the key entirely rather than falling back to a remote mirror. Managed OpenCode
uses its own built-in list. If you want a curated catalog for a locked-down
deployment, point `OPENCODE_MODELS_URL` at your own internal mirror — see
[Use local models](/start-here/connect-your-stack/use-local-models) and
[Air-gapped deployment](/start-here/air-gapped-deployment).

## The free-inference route is opt-in

There is a code path for a hosted "free" model route, but it is **off unless you
turn it on** and it has no default origin:

```bash
OPENWORK_ENABLE_FREE_INFERENCE=1 \
OPENWORK_FREE_INFERENCE_ORIGIN=https://your-gateway.example \
openwork-server
```

With neither set, the route resolves to an inert sentinel and makes no network
request at all.

## If you meant to use OpenCode models

Connect the `OpenCode Go` provider instead. Follow
[Using OpenCode Zen & Go Models](/start-here/connect-your-stack/using-opencode-zen-go-models)
to add the provider.

- [opencode.ai/go](https://opencode.ai/go)
- [opencode.ai/auth](https://opencode.ai/auth)

## If you operate a gateway

Then you own the catalog. Point a provider at it:

```jsonc
{
  "provider": {
    "my-gateway": {
      "options": { "baseURL": "https://gateway.internal/v1" },
      "models": { "my-model": { "name": "My Model" } }
    }
  }
}
```

See [Add a custom LLM](/start-here/connect-your-stack/add-a-custom-llm).
