<Note>
This fork tracks the **local, self-hosted** product. OpenWork's hosted
control plane, hosted workspaces, Slack, and organization features are not part
of it. Anything described upstream as a cloud capability is either absent here
or reduced to configuration you own.
</Note>

## What works today

| Capability | What it does | Status |
| --- | --- | --- |
| Desktop app for macOS, Windows, and Linux | A complete local-first workspace for agentic work. | Live |
| `openwork-server` | The headless backend. Serves the web UI, runs the agent runtime, holds your state. | Live |
| Local files and workspaces | Work directly in the files and repositories already on your computer. | Live |
| Local models | Ollama or any OpenAI-compatible server on your own hardware. | Live |
| Your own gateway | Point a provider `baseURL` at LiteLLM, Bifrost, or anything else. | Live |
| Skills | `SKILL.md` directories the agent reads. | Live |
| MCP servers | Local or remote MCP connections you configure. | Live |
| Artifacts | Preview, edit, download, and reopen generated files. | Live |
| Built-in browser control | Agents navigate, click, type, and capture in a visible browser. | Live |
| Scheduled tasks | Run a prompt on a schedule or trigger. | Partial |
| Isolated sandbox workspaces | Run work in a separate Docker or microsandbox environment. | Partial |

## What was removed with the control plane

These are not "coming later" — they are gone, and their replacement is your own
infrastructure:

| Removed | What you do instead |
| --- | --- |
| OpenWork Cloud and hosted workspaces | Run `openwork-server` yourself. See [Self-host](/start-here/self-host). |
| Hosted sign-in and device-code bootstrap | Nothing. The server authorizes the local client. |
| Organizations, teams, roles, Collections | Copy configuration. See [Share your setup](/start-here/do-work-with-it/share-your-setup). |
| Managed model catalog (`models.openworklabs.com`) | Unset `OPENCODE_MODELS_URL`, or point it at your own mirror. |
| Hosted free inference | Opt in with `OPENWORK_ENABLE_FREE_INFERENCE=1` plus your own origin. |
| OpenWork Gateway | Run a gateway of your own; it is just another outbound host. |
| OpenWork Connect MCP (`api.openworklabs.com/mcp/agent`) | Run an MCP server you control. |
| The `openwork-ee` Helm chart and AWS ECS Terraform module | Your own infrastructure around the npm package or container image. |
| Slack, mobile, and hosted cloud chat | Not part of this fork. |
| SSO, SCIM, desktop policy enforcement, audit logs | An authenticating reverse proxy, configuration files, and your own logs. |
| PostHog analytics | Nothing is sent. The project key is not baked in. |

See [Pricing and licensing](/start-here/pricing-and-licensing) for the full
mapping, and [Stewardship](/start-here/stewardship) for why the license is now
uniformly MIT.

## Principles for changes in this fork

1. **No default may point at a host we do not control.** If a feature needs a
   remote origin, it is opt-in and the variable is named.
2. **No telemetry, no analytics, no crash reporting to anyone but you.**
3. **One binary and one data path.** Adding a required external service is a
   regression.
4. **Every outbound host is declared** in
   `docs/enterprise/outbound-access.json` and checked by
   `node scripts/check-outbound-access.mjs`. If CI fails on that check, you
   added an undeclared destination.
